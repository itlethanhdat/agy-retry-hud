# Unified Plan: H1 (web actions) + H2 (setup center) + P3 (deep agy-retry-hud integration)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the agybox roadmap in one pass: the web hub gains real actions (H1), a single-click Setup Center (H2), and agybox integrates deeply with agy-retry-hud instead of duplicating its logic (P3).

**Architecture:** All three parts share two integration seams:
1. **Rotate-request bus** (`~/.agy-sandbox/rotate-request.json`, H1-1): the single cross-process "rotate now" signal. The hub (H1-2), the agybox supervisor, and the agy-retry-hud daemon (P3-3) all speak it — no new IPC per part.
2. **Shared modules, one implementation**: hub and CLI keep calling the same `agybox/lib/*` modules (established principle). P3 extends this across the repo boundary: agybox reuses `src/native.js#quotaFromStatus` instead of its duplicate parser.

```
browser ──HTTP/SSE──▶ agybox hub ──┬─ rotate-request ──▶ agybox run (supervisor)
                                   ├─ session child ──▶ node bin/agybox run (full auto-rotate)
                                   └─ setup tasks (async + SSE)
agy-retry-hud daemon ── retry.policy=rotate ──▶ rotate-request ──▶ supervisor
```

**Tech Stack:** Node.js ≥ 18, ESM, zero runtime dependencies (both `agybox/` and repo root). Tests: `node --test` (`agybox/test/*.test.js` for agybox; root `npm test` for `src/` changes).

**Spec:** `agybox/DESIGN-hub.md` (§2 API table, §3 screens, §4b workspace model, §5 security), `agybox/DESIGN-rotation.md` (§6 state machine, §8 UX, §11 P3). For P3 tasks touching `src/`, also read the repo's `spec.md`/`plan.md` first (per `AGENTS.md`; v0.4.0 behavior is normative).

## Review Focus

1. **Orphaned `agybox run` child when the hub dies.** The hub spawns the supervised session as a child process. If the hub crashes, the child (and its `docker exec`) keeps running detached. A reasonable person expects `GET /api/session/status` to still find it after a hub restart (via pid file + `pidAlive`), and `POST /api/session/stop` to kill it — not a ghost session, and not a second session spawned on top. → H1-3 test: kill hub (not the child), restart, status still reports running, stop works.
2. **Stale rotate-requests.** A request file written by an older supervisor run (or a crashed one) must not trigger a surprise rotation in a fresh run. A reasonable person expects requests older than 60s — or older than the supervisor's own start — to be ignored and consumed. → H1-1 test.
3. **Config PUT validation.** An invalid rotation policy (unknown account in `order`, negative cooldown) must be rejected with 400 and never partially applied. A reasonable person expects validate-then-atomic-write. → H1-2 test.
4. **P3 daemon rotate with no supervisor running.** Emitting a rotate-request nobody consumes must not lose the retry. A reasonable person expects fallback to the normal WAIT_QUOTA schedule with a logged reason. → P3-3 test.
5. **Setup steps must not brick the system.** Steps run shell/docker commands. A reasonable person expects every step to have a `check()` precondition, a dry-run mode, and to never run anything destructive unless explicitly invoked — with manual instructions when automation isn't possible. → H2-2 test.
